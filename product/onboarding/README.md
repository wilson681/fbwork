# 戒赌 App · Onboarding 需求验证原型

一个单文件网页。**目的不是上线，是在写第一行 app 代码之前，拿到三个真实数字。**

```
product/onboarding/index.html   ← 全部内容，零依赖，双击就能开
```

---

## 它是什么

完整的转化漏斗，跑在浏览器里：

```
开场 → 18 个问题 → 分析动画 → 个性化诊断 → 损失账单 → 90 天计划 → 付费墙 → 留资
```

四个设计决策，每一个都有理由：

| 决策 | 为什么 |
|---|---|
| 付费墙在 onboarding 之后，不在下载时 | App Store 上付费下载没有自然流量。正确形态是免费下载 → onboarding 制造投入 → 硬付费墙 |
| 总损失让用户自己填，不由系统估算 | 他自己算出来的数字他才信。这是整个漏斗情绪强度最高的一屏 |
| 配色避开红 / 金 / 桌绿 | 那是赌场色系。用冷静的深蓝灰，不触发条件反射 |
| 奖励全部固定可预期，无随机 | 可变比率强化就是老虎机的机制。用它治赌瘾等于在复现病因 |

---

## 怎么测

**本地看效果**：直接用浏览器打开 `index.html`。控制台输入 `qbData()` 导出全部埋点为 CSV。

**拿真人测**：
1. 传到任意静态托管（GitHub Pages / Vercel / Cloudflare Pages 都行，单文件无需构建）
2. 打开 `index.html` 顶部的 `CONFIG.ENDPOINT`，填一个能收 POST JSON 的地址（Formspree、自建接口都行）。留空则只写 localStorage
3. 拍 3–5 条短视频导流。内容方向：把损失账单那一屏当钩子
4. **目标样本量 500 人**，大约 2 周

---

## 要看的三个数字

| 指标 | 及格线 | 说明 |
|---|---|---|
| **完成率**（到达付费墙 / 开始） | > 55% | 低于 40% 说明题目太长或太冒犯，砍题 |
| **付费点击率**（点了价格 / 到达付费墙） | > 8% | 低于 4% 说明诊断不够扎心，或价格离谱 |
| **留资率**（留联系方式 / 点了价格） | > 40% | 这是最硬的信号——愿意留下联系方式的人是真的想要 |

**三个都过线 → 开始写 app。有一个不过 → 先改这一页，不要写 app。**

## 价格 A/B 测试

三档随机分配，记录点击：

| 变体 | 年费 | 月费 |
|---|---|---|
| A | ¥148 | ¥38 |
| B | ¥288 | ¥68 |
| C | ¥398 | ¥98 |

看的不是哪档点击率最高（一定是最便宜的那档），而是 **点击率 × 价格 = 每千次曝光收入**。便宜一半但点击率只高 30%，那就是亏的。

在 `CONFIG.PRICES` 里改数值。

### 为什么 ¥148（≈$20/年）我不推荐

- AI 对话有边际成本。重度用户一年烧掉 $24–36 的推理费，**在这个价位上，你最投入的用户每一个都在让你亏钱**
- 扣掉平台 15% 抽成后：$20 → $17 → 减去平均 $9 推理成本 → 剩 $8
- 戒赌的结构优势就是痛感等于大钱。按大众消费品定价，等于把这个优势扔了
- 做到 50 万美元年收入：$20/年需要 2.5 万付费用户（≈50 万下载）；$56/年只需要 9 千（≈18 万下载）

但这是我的推理，不是数据。**跑完 500 人再定。**

## 上线前必须做的三件事

1. **核实所有求助热线号码**，并按目标市场替换。付费墙里那三个是占位，必须逐一验证
2. **中性化商户名**。用户信用卡账单上如果出现 "QuitGambling"，全部隐私承诺一秒归零
3. **删掉开场那句「已有 2,847 人完成」**，或者换成真实数字。上线前它是虚构的社会证明，不能留
